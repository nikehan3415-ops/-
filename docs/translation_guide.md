# 테일즈 오브 판타지아 (GBA, 일본판) 한글화 번역 지침

## 1. 대상 및 파일

| 항목 | 내용 |
|---|---|
| ROM | Tales of Phantasia (GBA) 일본판, 게임코드 `AN8J`, MD5 `68bdd417dd5bf3d1c88fd0b2a800e17c` |
| 대사 CSV | `script/dialogue.csv` (UTF-8 BOM, 12,225행 / 문자열 4,970개 / 54블록) |
| 문자 테이블 | `tables/top_jp.tbl` (16비트 LE 코드 → 문자) |
| 도구 | `tools/top_text.py` (추출·왕복검증·번역검사) |

ROM 파일은 저장소에 올리지 않습니다(`.gitignore`에서 `*.gba` 제외 처리).

### CSV 열

| 열 | 설명 | 수정 여부 |
|---|---|---|
| `id` | `블록-서브-문자열오프셋-페이지` | 수정 금지 |
| `block`, `sub`, `sub_addr`, `str_off`, `page` | 재삽입할 때 쓰는 위치 정보 | 수정 금지 |
| `speaker` | 화자(참고용으로 자동 추출함, 재삽입에 쓰지 않음) | 수정 금지 |
| `japanese` | 원문. 검증 기준이므로 절대 수정하지 않습니다 | 수정 금지 |
| `korean` | **번역을 입력하는 열** | 입력 |
| `note` | 번역자 메모(애매한 부분, 확인할 점) | 자유롭게 입력 |

- 1행이 대화창 1페이지(`{W}`까지)입니다. 같은 `str_off`의 행들을 `page` 순서대로 이어 붙이면 게임 안에서 문자열 1개가 됩니다.
- 행을 추가하거나 삭제하거나 순서를 바꾸면 안 됩니다. 페이지를 늘리거나 줄여야 하면 `note`에 적어 주세요(2차 작업에서 처리).
- Excel로 편집할 경우 **UTF-8 CSV**로 저장하세요. 셀 안의 줄바꿈(Alt+Enter)이 게임의 줄바꿈입니다.

## 2. 제어 코드(태그): 원문에 있는 그대로 유지

| 태그 | 원 코드 | 의미 | 규칙 |
|---|---|---|---|
| (셀 안 줄바꿈) | `0003` | 줄바꿈 | 1페이지는 최대 3줄(화자 줄 포함) |
| `{W}` | `0004` | 키 입력 대기 후 다음 페이지 | 개수와 위치(행 끝)를 원문과 같게 |
| `{N1}`~`{N6}` | `0007 n` | 파티원 이름 | 1 클레스, 2 민트, 3 아체, 4 클라스, 5 체스터, 6 스즈 |
| `{ITEM:xx}` | `0008 n` | 아이템 이름 삽입 | 그대로 둡니다 |
| `{TITLE:xx}` | `0009 n` | 칭호 이름 삽입 | 그대로 둡니다 |
| `{COL:2}` … `{COL:0}` | `0006 n` | 글자색 시작/복귀 | 강조할 단어를 감싸는 위치만 옮길 수 있음 |
| `{SPD:xx}` | `0005 n` | 출력 속도(`10`=느리게, `FF`=원래대로) | 보통 「…」 연출에 쓰임, 그대로 둡니다 |
| `{NUM:xx}` | `000A` + u32 | 숫자 표시 | 그대로 둡니다 |
| `{VAR:…}`, `{EXB:…}`, `{EXC:…}`, `{EXD:…}` | `000B`~`000E` + 스크립트 식 | 변수 값 표시(돈 등) | 절대 수정 금지 |
| `{C:F}` | `000F` | 튜토리얼 문장 끝 코드 | 그대로 둡니다 |
| `{G:6CB}` 등 | 미확인 글리프 | 볼트(ヴォルト)가 쓰는 기호 문자 등 | 원문 그대로 둡니다 |

- 조사 처리: `{N3}`은 "아체", `{N4}`는 "클라스"처럼 받침이 없어서 `{N1}`(클레스)와 조사가 같습니다. 모든 이름이 모음으로 끝나므로 이름 뒤에는 **받침 없는 조사**(는/가/를/와/야)를 씁니다.
- `{ITEM}`/`{TITLE}` 뒤에는 받침 여부를 알 수 없으므로 `을(를)`처럼 병기하거나, 조사가 필요 없는 문장으로 바꿉니다. 예: 「{ITEM:xx} 입수!」

## 3. 서식 제한 (검사기가 자동으로 확인)

- **1줄 17칸**(전각 기준). 원문 대사 줄의 99.8%가 17자 이내입니다. 한글 1자, 전각 문장부호 1개, 공백 1개를 각각 1칸으로 셉니다(한글 폰트가 확정되면 다시 조정).
- 이름 태그는 실제 이름 길이로 계산합니다(체스터=5칸). `{ITEM}`/`{TITLE}`은 8칸으로 잡습니다.
- **1페이지 3줄**이며, 화자가 있는 페이지는 1줄째가 화자 이름입니다. 따라서 대사는 2줄까지 들어갑니다.
- 원문의 두 번째 줄 시작 전각 공백(`　`)은 「」 안쪽 들여쓰기입니다. 번역에서도 유지합니다.
- 제작진 목록, 표지판처럼 원래 17자를 넘는 특수 화면은 원문 크기까지 허용합니다.

## 4. 문체

| 항목 | 규칙 |
|---|---|
| 괄호 | 대사 「」, 책·간판 『』, 생각은 원문 기호를 유지 |
| 말줄임 | 원문 `・・・` → `…` 또는 `...` 중 하나로 통일(권장 `…`, 1칸) |
| 느낌표/물음표 | `！？` → `!?` 전각/반각 중 하나로 통일(폰트가 확정되면 결정) |
| 숫자 | 한국식 표기(５００００ガルド → 50000갈드) |
| 의성어·감탄사 | 한국어 감탄사로 바꿔 씁니다(えッ → 엇, うーん → 으음) |
| 사투리 | おじいさん의 관서 사투리(ほんま, のぅ) 같은 말투는 노인 말투 등 한국어 말투로 옮깁니다 |

## 6. 작업 흐름과 검증

```bash
# (최초 1회) ROM에서 추출
python3 tools/top_text.py extract Tales_of_Phantasia.gba script/dialogue.csv

# 추출 무결성 검증: japanese 열을 다시 인코딩해 ROM과 바이트 단위로 비교
python3 tools/top_text.py verify Tales_of_Phantasia.gba script/dialogue.csv
#  -> strings=4970 errors=0 ... RESULT: PASS

# 번역 검사: 태그 일치, {W} 개수·위치, 괄호 태그 손상, 줄 길이(17), 줄 수(3)
python3 tools/top_text.py check script/dialogue.csv
```

- 번역을 커밋하기 전에 `check`가 `RESULT: PASS`인지 반드시 확인합니다. 실패한 행은 `[id] 사유` 형식으로 출력됩니다.
- `verify`는 `japanese` 열이 손상되지 않았는지 확인합니다. CSV를 다른 프로그램으로 저장한 뒤에도 실행하세요.

## 7. 확인된 사항과 남은 과제

- **확인됨**: 대사 전체(0x6C7EC4~0x7BC4F2, 54블록)가 비압축 16비트 형식입니다. 추출과 재인코딩 결과가 ROM과 100% 일치합니다.
- **문맥으로 추정한 한자**(ROM 디버그 테이블에 없음): 06CA 杯, 06CF 販, 06D3 掴, 06D4 貰, 06D7 療, 06DC 余, 06FA 齢, 06FB 叔, 06FC 詮, 06FD 薪, 06FE 岐, 06FF 罰. 폰트 그래픽으로 최종 확인이 필요합니다.
- **미확인**: `{G:6D1}`(문맥상 恨 또는 憎, "〜んでいる"), `{G:6CB}`~`{G:6CE}`(볼트의 기호 문자).
- **재삽입할 때 주의**: 스크립트가 문자열을 텍스트 영역 기준 **바이트 오프셋(u16)**으로 참조합니다(예: opcode `11 <off>`). 번역문 길이가 바뀌면 스크립트 안의 오프셋을 다시 계산하고 블록 포인터(0x27474C)도 옮겨야 합니다. 이 작업은 삽입기 개발 단계에서 합니다.
- **한글 폰트**: 테이블 영역은 0x06D0자 이상이며, 한글 2,350자(KS X 1001)나 사용 빈도 상위 글자를 넣으려면 폰트와 테이블을 확장해야 합니다.
- **범위 밖**: 메뉴, 아이템, 기술, 몬스터 이름 등 시스템 텍스트(0x2A0000 부근, 같은 16비트 인코딩)는 별도 CSV로 추출할 예정입니다.
